# 데이터 테이블

기준 파일: `src/components/data-table.tsx`
현재 동작하는 기능: 페이지네이션 · 열 표시 토글 · 행 선택 · 행 드래그 순서 변경 · 이름 클릭 상세 드로어.
정렬·필터는 TanStack feature와 상태만 등록되어 있고, 사용자가 조작할 입력이나 헤더 버튼은 아직 없어요.

## 주의 — TanStack Table v9

이 프로젝트는 v9입니다. 웹 검색으로 나오는 예제 대부분(v8, `useReactTable`)과 다릅니다.

```tsx
// v9: 쓸 기능을 명시적으로 등록 (등록 안 한 기능은 번들에서 제거됨)
const features = tableFeatures({
  rowSortingFeature,
  rowPaginationFeature,
  sortedRowModel: createSortedRowModel(),
  // …
})
const table = useTable({ features, data, columns, … })
```

새 기능(예: 전역 검색)이 필요하면 해당 feature를 `tableFeatures()`에 추가하는 것부터 시작하세요.

## 열 추가/수정 체크리스트

1. `schema`(zod)에 필드 추가 — 데이터 검증의 기준.
2. `columns` 배열에 `columnHelper.accessor(...)` 추가.
3. `columnLabels`에 한국어 열 이름 추가 — "표시 열" 드롭다운에 나오는 이름.
4. `data.json`(또는 API 응답)에 해당 필드 포함.
5. 드로어(`TableCellViewer`)의 수정 폼에도 필드를 넣을지 결정.

## 한국어 텍스트 처리

- 셀이 길어질 수 있으면 `<div className="max-w-48 truncate" title={값}>`.
  잘림 대신 말줄임 + 마우스오버 전체 보기가 원칙입니다.
- 상태 값("완료" 등)은 코드의 비교 문자열과 데이터 값이 정확히 일치해야 합니다 —
  `status === "완료"` 같은 분기가 있어요.

## 예시 UI와 저장 범위

목표·상한 입력에서 Enter를 누르면 저장 토스트가 나오지만, 현재는 타이머로 완료를 보여주는 예시예요.
행 데이터나 서버에 값을 저장하지 않아요. 담당자 선택과 상세 드로어의 입력·저장 버튼도
행 갱신이나 API와 연결되어 있지 않아요.

`데이터셋 추가`와 행 메뉴의 수정·복제·즐겨찾기·삭제에는 처리 핸들러가 없어요.
표 안의 월간 리포트·담당자별·즐겨찾기 탭은 빈 예시 패널이며,
좁은 화면의 보기 선택 드롭다운은 해당 탭 상태와 아직 연결되어 있지 않아요.

행 선택·드래그 순서·페이지·표시 열은 현재 탭 간 이동 동안 유지되지만 새로고침하면 초기화돼요.
상단의 `샘플 CSV`는 화면 편집 결과가 아니라 원본 `data.json`을 내보내요.

## 서버 연동 시 확인할 점

지금은 `data.json`의 20행을 클라이언트에서 처리해요. `DataTable`은 전달받은 `data`를
`useState(() => initialData)`로 최초 한 번만 복사하므로, 빈 배열로 먼저 렌더링한 뒤
fetch 결과를 prop으로 바꾸는 것만으로는 표가 갱신되지 않아요. 응답을 받은 뒤 처음 마운트하거나,
갱신 시 행 선택·순서 유지 정책을 정한 후 내부 상태를 동기화하도록 수정하세요.

`schema`는 현재 TypeScript 타입 추론에 사용돼요. 서버 응답의 런타임 검증은 별도로
`schema.array().parse(...)` 또는 `safeParse(...)`를 호출해야 해요.
실제 수정·추가·삭제에는 입력 검증, API 요청, 성공 후 행 갱신, 오류 처리를 연결하세요.

전체 응답 크기와 실제 렌더링 성능을 측정해 클라이언트 처리와 서버 처리를 선택하세요.
서버 페이지네이션을 쓰면 `manualPagination`과 전체 행 수를 설정하고, 페이지 변경에 맞춰
데이터를 다시 요청해야 해요. 정렬·필터를 서버에 맡길 때는 해당 UI와 `manualSorting`·
`manualFiltering` 설정, 요청 파라미터를 함께 구현하세요.

## 행 드래그 정렬이 필요 없다면

`DndContext`·`SortableContext`·`DragHandle`·`drag` 열을 지우면 코드가 크게 단순해집니다.
조회 전용 대시보드라면 지우는 걸 권장해요.
