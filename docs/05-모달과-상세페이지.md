# 모달과 상세 페이지

`#modals`에서 입력·삭제 확인·완료 모달을, `#detail`에서 이미지가 포함된 상세 화면을 살펴봐요.
두 화면은 사내 서비스에 가져다 쓸 수 있는 독립 예시이며, 백엔드와 연결되어 있지 않아요.

## 화면에서 사용하기

### 모달 예시

1. **컬렉션 만들기** 또는 **컬렉션 추가**를 눌러 입력 모달을 열어요.
2. 이름은 필수이며 최대 60자, 설명은 선택이며 최대 500자예요. 이름이 비었거나 공백뿐이면 오류를 표시하고 이름 입력으로 포커스를 이동해요.
3. 제출하면 앞뒤 공백을 정리한 컬렉션이 화면의 목록에 추가되고 완료 모달로 바뀌어요. **목록에서 확인하기**를 누르면 모달이 닫혀요.
4. 목록의 휴지통 버튼으로 해당 항목의 삭제 확인을 열어요. 위쪽 카드의 **삭제 확인 열기**는 목록 첫 항목을 대상으로 해요. **취소**하면 유지되고, **컬렉션 삭제**를 누르면 예시 목록에서 제거돼요.
5. **완료 상태 보기**는 완료 모달만 미리 보여줘요. 컬렉션을 추가하지 않아요.

처음에는 `월간 매출 분석` 컬렉션 하나가 있어요. 모두 삭제하면 빈 상태와 새 컬렉션 만들기 버튼이 나와요.
삭제한 항목을 되돌리는 별도 복구 기능은 없어요. 만든 항목과 삭제 결과는 `ModalExamples`의 메모리에만 있으며,
다른 메뉴로 이동하거나 새로고침하면 초기 예시 목록으로 돌아가요.

### 이미지 상세 페이지

- 이미지를 누르거나 **크게 보기**를 누르면 확대 모달이 열려요. 제목과 설명, 닫기 버튼을 제공해요.
- **소개**·**필드 정의**·**변경 이력** 탭으로 활용 설명, 필드 5개, 변경 기록을 확인해요.
- **관심 데이터**를 누르면 **관심 해제**로 바뀌어요. 이 표시는 현재 화면에서만 유지돼요.
- **샘플 CSV 받기**는 `warehouse-operations-sample.csv`라는 이름으로 물류 예시 3행을 내려받아요. 표시된 전체 행 수 12,480행을 내보내는 기능은 아니에요.
- **데이터셋 목록**은 `#datasets`, **모달 예시 둘러보기**는 `#modals`로 이동해요.

상세 페이지는 표의 특정 행을 선택해 여는 화면이 아니에요. 기존 표의 이름 클릭은 그대로 드로어를 열고,
`#detail`은 별도 물류 예시 데이터를 보여줘요. 실제 서비스에서 행별 상세 페이지가 필요하면 식별자와 조회를 연결하세요.
상단 공통 **샘플 CSV**는 `data.json`의 데이터셋 목록 20행을 내보내므로 상세 화면의 물류 CSV와 구분해요.

## 공용 모달을 가져다 쓰기

`ExampleDialog`는 Radix `Dialog`를 감싼 제어형 컴포넌트예요. 입력·완료 안내·이미지 확대에 사용해요.
삭제 확인 예시는 같은 화면 스타일을 쓰되, 별도의 Radix `AlertDialog`로 구현되어 있어요.

| 속성 | 필수 | 역할 |
|---|---|---|
| `open` | 예 | 모달 표시 여부 |
| `onOpenChange` | 예 | 닫기·Esc·외부 클릭 등에 따른 상태 변경 처리 |
| `title` | 예 | 모달 제목 문자열 |
| `description` | 예 | 목적을 설명하는 React 내용. 짧은 문장을 권장해요 |
| `children` | 예 | 본문 |
| `footer` | 아니요 | 하단 액션 버튼. 생략하면 푸터가 없어요 |
| `className` | 아니요 | 모달 전체 스타일. 기본 최대 너비는 `max-w-lg`예요 |
| `bodyClassName` | 아니요 | 본문 스타일. 이미지 확대는 `p-0`을 사용해요 |
| `closeLabel` | 아니요 | 우상단 닫기 버튼의 접근성 이름. 기본값은 `닫기`예요 |
| `fallbackFocusRef` | 아니요 | 열었던 버튼이 없어지거나 비활성화됐을 때 포커스를 받을 요소의 ref예요 |

아래 예제는 버튼으로 열고 닫는 안내 모달이에요. 저장이나 API 요청은 수행하지 않아요.

```tsx
import { useState } from "react"
import { ExampleDialog } from "@/components/reference/example-dialog"
import { Button } from "@/components/ui/button"

export function DatasetNotice() {
  const [open, setOpen] = useState(false)

  return (
    <>
      <Button type="button" variant="outline" onClick={() => setOpen(true)}>
        데이터 안내
      </Button>
      <ExampleDialog
        open={open}
        onOpenChange={setOpen}
        title="데이터 이용 안내"
        description="조회 전에 데이터의 범위와 기준일을 확인해 주세요."
        footer={
          <Button type="button" onClick={() => setOpen(false)}>
            확인했어요
          </Button>
        }
      >
        <p className="text-sm leading-relaxed text-muted-foreground">
          이 데이터는 화면 구성을 확인하기 위한 예시예요.
        </p>
      </ExampleDialog>
    </>
  )
}
```

입력 모달은 `modal-examples.tsx`의 `<form onSubmit={createCollection}>`을 참고하세요.
푸터는 본문 폼 바깥에 있으므로 제출 버튼에 `type="submit"`과 `form={formId}`를 함께 지정해요.
너비는 `className="max-w-5xl"`처럼 Tailwind 스케일로 확장하고, 높이는 화면 안에서 본문이 스크롤하도록 유지하세요.

## 이미지와 상세 데이터를 교체하기

1. 이미지를 `public/images/`에 넣어요. `detail-data.ts`의 `image`에는 `images/새파일.png`처럼 `public/`과 앞쪽 `/`를 제외한 경로를 적어요.
2. `imageAlt`는 실제 이미지 내용을 설명하도록 바꿔요. 이름·소개·담당 팀·원천·행 수·갱신일·필드 정의도 같은 파일에서 바꿔요.
3. 현재 원본은 **1536 × 1024 PNG**이고, 실제 시설을 나타내지 않는 AI 생성 이미지예요. 다른 이미지를 쓰면 컴포넌트의 `width`·`height`, 이미지 캡션과 생성 출처 안내를 실제 자료에 맞춰 수정해요. 출처 기록 파일에도 새 자료의 출처나 생성 정보를 기록하세요.
4. 페이지 제목은 `dashboard-navigation.ts`, 변경 이력과 활용 설명·일부 기본 정보는 `dataset-detail-page.tsx`에 있어요. `detail-data.ts`만 바꿔도 모든 문구가 바뀌는 구조는 아니에요.
5. 내려받기 파일은 `public/samples/warehouse-operations.csv`를 교체해요. 필드 정의와 열 이름·단위·행 수 안내, 링크의 파일명도 함께 맞춰요.

이미지와 CSV 주소는 `import.meta.env.BASE_URL`을 붙여 만들기 때문에 Vite의 하위 경로 배포 설정을 따라가요.
요약 이미지는 `object-cover`로 잘라 보여주고, 확대 모달은 `object-contain`으로 원본 비율을 유지해요.
이미지 로딩에 실패하면 안내를 표시하고 확대 버튼을 비활성화해요.

## 실제 API를 연결할 위치

| 작업 | 현재 예시 | 연동할 지점 |
|---|---|---|
| 컬렉션 생성 | `createCollection`이 메모리 목록에 추가 | 검증 후 생성 API를 호출하고 성공 응답으로 목록·완료 모달을 갱신해요 |
| 컬렉션 삭제 | `deleteCollection`이 메모리 목록에서 제거 | 삭제 API 성공 후 목록에서 제거해요. 진행·실패 상태와 확인 모달의 닫힘 시점도 함께 제어해요 |
| 관심 데이터 | `DatasetDetailPage`의 `saved` 상태 토글 | 조회한 관심 상태를 초기값으로 사용하고 변경 API 성공 후 반영해요 |
| 상세 정보·이력 | `detailDataset`, `updateHistory` 상수 | 데이터셋 ID로 조회하고 로딩·빈 결과·오류 화면을 추가해요 |
| CSV | 공개 샘플 정적 파일 다운로드 | 실제 내보내기 범위와 접근 권한에 맞는 다운로드 API로 연결해요 |

비동기 작업을 연결할 때는 처리 중 중복 제출을 막고, 실패 메시지를 모달 안에서 보여줘요.
현재 `ExampleDialog`의 닫기 동작은 기본적으로 허용되어 있어요. 처리 중 닫기 제한이 필요하면
`onOpenChange`와 작업 상태를 함께 관리하세요. 실제 저장은 완료 안내가 아니라 서버 응답을 기준으로 해요.
조회 연동의 로딩·검증 예제는 [README의 API 연결](../README.md#4-사내-api-연결하기)을 참고하세요.

## 접근성과 반응형 확인

- `ExampleDialog`의 제목과 설명을 생략하지 않아요. 아이콘만 있는 닫기 버튼에는 `closeLabel`로 작업에 맞는 이름을 줄 수 있어요.
- 일반 모달은 Esc·우상단 닫기·바깥 영역 클릭으로 닫을 수 있어요. Radix가 모달 내부 포커스 이동을 관리하고, 셸은 닫은 뒤 열기 전 요소로 포커스를 돌려줘요. 열었던 버튼이 조건부로 사라질 수 있다면 `fallbackFocusRef`를 지정해요. 컬렉션 예시는 항상 남아 있는 컬렉션 추가 버튼을 사용해요.
- 삭제 확인은 `AlertDialog`를 사용해 바깥 클릭으로 닫히지 않아요. 취소가 기본 포커스를 받고, 삭제 뒤 원래 버튼이 사라지거나 비활성화됐다면 컬렉션 추가 버튼으로 포커스를 옮겨요.
- 입력은 `Label`과 연결하고, 오류는 `aria-invalid`·`aria-describedby`·`role="alert"`로 알려줘요. 이름 오류가 나면 해당 입력으로 포커스를 돌려요.
- 관심 표시는 `aria-pressed`, 목록 변경 안내는 `role="status"`로 상태를 전달해요. 색만으로 성공·실패를 구분하지 않아요.
- 긴 설명·긴 이름·모바일 화면에서도 모달 본문을 스크롤할 수 있는지, 푸터 버튼과 닫기가 가려지지 않는지 확인해요. 라이트·다크와 컬러 테마에서도 같은 동작을 확인하세요.
