# 레퍼런스 부품

`src/components/reference/`에 있는 부품들입니다.
화면에서 실제로 어떻게 보이는지는 사이드바나 상단 탭의 **부품 라이브러리**(`#reference`)에서
한 번에 확인할 수 있어요. 화면 코드는 `src/components/reference-gallery.tsx`예요.
공용 모달 셸은 **모달 예시**(`#modals`)와 **상세 페이지**(`#detail`)의 이미지 확대에서 확인해요.

## 어디서 왔나

인스타그램 UI 레퍼런스 다섯 편에서 규칙을 뽑아 왔습니다.

| 출처 | 가져온 것 |
|---|---|
| rondesignlab · CreditPros (모바일/데스크톱) | KPI 카드 해부도, 다중 선형 차트, 구간 게이지, 달력형 타임라인, 그라디언트 상세 카드 |
| rondesignlab · 스마트보틀 | 실측→예측 차트, 메시 그라디언트 지표 타일, 요일 선택기 |
| theuinspo · Ventra 팩토리 대시보드 (arounda) | 레이아웃 문법, 알약 내비게이션, 사용자 칩, 해치 막대 차트, 점검 매트릭스, 경고 카드, 속성 목록 |
| tranmautritam · liquid button | 리퀴드 캡슐 (메시 그라디언트 + 흐름 애니메이션) |

**형태·레이아웃 규칙은 레퍼런스에서 가져왔고, 기본 색상은 블루 계열이에요.**
헤더에서 바이올렛·틸·로즈·앰버도 선택할 수 있어요.
라이트 배경은 레퍼런스의 따뜻한 오프화이트 `#FBFAF6` 그대로, 다크는 원본의
무광 블랙(`#0A0E06`)이 너무 어두워서 `#15171B`로 한 단 올리고
색조도 파랑에 맞춰 중성 회색으로 옮겼어요.

## 색 토큰

색상 값의 기준은 `src/index.css`예요. 기본 블루의 `:root` / `.dark` 값과
선택 팔레트의 `:root[data-color-theme="..."]` / `:root.dark[data-color-theme="..."]`를 확인하세요.
색상마다 라이트·다크 값이 달라지므로 고정 hex 값을 컴포넌트에 복사하지 않아요.

| 토큰 | 쓰는 곳 |
|---|---|
| `--brand` / `--brand-foreground` | 강조 버튼·텍스트와 그 위의 글씨 |
| `--brand-hover` / `--brand-soft` | 강조 버튼의 호버와 옅은 강조 면 |
| `--highlight` | 차트 강조 지점 배지 |
| `--success` / `--success-soft` | 완료·정상, 게이지 상위 구간 |
| `--warning` / `--warning-foreground` | 주의 배지와 그 위의 글씨 |
| `--destructive` | 실패·경고 |
| `--chart-1`~`3` | 선택한 색상 테마에 맞춘 서로 다른 차트 계열 |
| `--chart-4`~`5` | 비교용 중립색 계열 |
| `--background` / `--card` | 바탕과 카드 면 |

**강조색과 상태색은 별도로 관리해요.** 색상 테마를 바꿔도 완료·정상은 `--success`,
주의는 `--warning`, 실패는 `--destructive`를 사용해요. 배경과 본문 색도 색상 테마와 별개예요.

차트는 `ChartContainer`와 `ChartConfig`로 각 계열을 토큰에 연결하세요.
기본 블루의 차트 1~3번은 블루·시안·바이올렛이고, 다른 테마에도 서로 구분되는 세 계열이 있어요.
테마를 조정할 때는 해당 CSS 변수만 수정하면 부품에도 반영돼요.

## 공통 규칙 5가지

1. **카드 골격은 하나** — 원형 아이콘 칩 + 제목 + 우상단 원형 ↗ 버튼.
   `Panel` / `PanelHeader` / `PanelCaption`으로 고정돼 있습니다.
2. **숫자는 크게, 단위는 작게** — `text-4xl` 숫자 옆에 `text-base text-muted-foreground` 단위.
   항상 `tabular-nums` + `toLocaleString("ko-KR")`.
3. **큰 숫자 옆엔 위치 표시** — 도트 매트릭스나 링 스텝을 붙여 "전체 중 어디쯤"을 같이 보여줍니다.
4. **색만으로 구분하지 않는다** — 상태는 색 + 아이콘 + 텍스트(또는 툴팁) 셋을 같이 씁니다.
5. **주의색은 글자색으로 쓰지 않는다** — 상태 토큰 `--warning`은 흰 배경에서 대비가 안 나와요.
   항상 `bg-warning text-warning-foreground`처럼 꽉 채워서 씁니다.

## 차트 쓰는 법

### 그래프 예시 모음

`src/components/chart-examples.tsx`의 `ChartExamples`는 누적 막대(요일별 처리량),
도넛(수집 소스 구성), 막대 + 선(평균·P95 응답 시간), 레이더(품질 점검 비교)를
두 열 반응형 카드로 보여줘요. `전체 / 비교·추이 / 분포·구성` 버튼으로 실제 예시를
필터링할 수 있고, 각 그래프는 독립적인 목업 데이터와 단위가 있는 툴팁을 포함해요.
모든 예시는 기존 `Panel`, `ChartContainer`, `ChartConfig`와 테마 토큰을 사용해요.

### 기본 차트 부품

셋 다 `ChartContainer` + `ChartConfig` 패턴을 지킵니다(하드 룰 6).

```tsx
// 1. 다중 선형 — 주계열만 진하게, 최댓값에 하이라이트 배지가 자동으로 붙어요
const config = {
  api:    { label: "API 연동",   color: "var(--chart-1)" },  // 주계열
  batch:  { label: "배치 적재",  color: "var(--chart-4)" },  // 비교용 (회색)
  manual: { label: "수기 업로드", color: "var(--chart-5)" },
} satisfies ChartConfig

<TrendLineChart data={rows} config={config} primaryKey="api" />
// focusIndex를 주면 강조 지점을 직접 지정할 수 있어요
```

```tsx
// 2. 실측 → 예측 — splitIndex까지 실선, 이후 점선
<ForecastChart data={[{ label: "6월 1일", value: 820 }, …]} splitIndex={5} />
```

```tsx
// 3. 해치 막대 — stage가 ChartConfig 키, value가 0~100
const config = {
  collect: { label: "수집", color: "var(--chart-1)" },
  clean:   { label: "정제", color: "var(--chart-2)" },
  load:    { label: "적재", color: "var(--chart-3)" },
} satisfies ChartConfig

<HatchBarChart data={[{ stage: "collect", value: 100 }, …]} config={config} />
```

`RadialGauge`도 같은 패턴이에요(`RadialBarChart`). 가운데 숫자만 SVG가 아니라
겹쳐 놓은 div인데, 한글이 훨씬 또렷하게 나오기 때문입니다.

> 모두 `isAnimationActive={false}`입니다. Recharts의 등장 애니메이션은
> 탭이 백그라운드일 때 `requestAnimationFrame`이 멈추면 0% 상태로 굳어
> 차트가 빈 화면으로 보이는 일이 있어요. 새 차트를 추가할 때도 꺼 두세요.

### Recharts를 쓰지 않는 시각화

`CompositionBar` · `RankingList` · `FunnelSteps` · `ScoreGauge` · `MatrixHeatmap` ·
`Sparkline`은 Recharts 없이 만들었어요. 축도 눈금도 범례도 없는 한 줄짜리 비율 막대나
80×28px짜리 추이선에 `ResponsiveContainer`를 얹으면 얻는 것 없이 리사이즈 관측만 늘어나거든요.
색은 그대로 `--chart-*` 토큰을 참조하므로 다크 모드는 알아서 따라옵니다.

**축이 있고 값이 여러 개면 Recharts, 한 줄짜리 비율·순위 표시면 CSS** — 이 선으로 나누세요.

## 그라디언트

메시 그라디언트는 `index.css`의 `.mesh-brand` `.mesh-cool` `.mesh-warm` 세 개뿐이에요.
컴포넌트에서 새 그라디언트를 만들지 말고 이 셋 중에서 고르세요.

**한 면에 쓰는 네 색은 색상환에서 서로 이웃한 것만 고릅니다.** 파랑과 노랑처럼
마주 보는 색을 한 면에서 섞으면 겹치는 자리가 회색으로 죽어 면 전체가 탁해져요.
그래서 세 변형은 각각 이런 램프입니다.

| 유틸리티 | 램프 | 쓰임 |
|---|---|---|
| `.mesh-brand` | 인디고 → 블루 → 하늘 → 시안 | 기본. 브랜드 면 |
| `.mesh-cool` | 시안 → 민트 → 블루 | 차분한 보조 면 |
| `.mesh-warm` | 바이올렛 → 자홍 → 코랄 | 온도만 올린 대비 면 |

이 색들은 **시맨틱 토큰을 따르지 않고** `--mesh-a` ~ `--mesh-d`로 따로 잡아 뒀어요.
강조색(`--brand`)을 바꿔도 메시는 자동으로 따라오지 않으니, 테마를 바꿀 땐
`index.css`의 `.mesh-*` 램프도 같이 조율하세요. 토큰을 그대로 물리면
강조색과 상태색(앰버·레드)이 한 면에서 만나 탁해집니다.

첫 배경 레이어는 어두운 스크림이에요. 흰 글씨 대비를 잡아 주되 색이 죽지 않게
최소한만 얹습니다. 세기는 `--mesh-scrim-from` / `--mesh-scrim-to`로 조절해요
(예: 면적이 작은 `.liquid-surface`는 거의 0에 가깝게).

## 애니메이션

전부 CSS만 씁니다. JS 타이머나 `requestAnimationFrame`에 기대지 않아요 —
탭이 백그라운드로 내려가면 rAF가 멈춰서 애니메이션이 중간 상태로 굳거든요.
(Recharts 차트에서 `isAnimationActive={false}`를 주는 것도 같은 이유예요.)

| 유틸리티 | 하는 일 | 붙는 곳 |
|---|---|---|
| `.mesh-drift` | 그라디언트가 24초에 걸쳐 아주 느리게 흐름 | 그라디언트 타일·요약 카드 |
| `.liquid-surface` | 같은 원리의 빠른 버전(9초) | 리퀴드 캡슐 |
| `.sheen` | 마우스를 올리면 광택이 한 번 훑고 지나감 | 그라디언트 타일 |
| `.grow-x` | 막대가 0에서 제 길이까지 자람 | 순위 목록·퍼널·단계 진행·요약 카드 진행 막대 |

`.grow-x`는 **너비를 건드리지 않아요.** 최종 너비는 값이 정하고(`style.width`),
이 클래스는 `scaleX`만 애니메이션합니다. 여러 개를 순서대로 등장시키려면
`style.animationDelay`로 시차를 주세요 — `RankingList`가 그렇게 하고 있어요.

호버 반응은 KPI 카드·그라디언트 타일에 `hover:-translate-y-*` + 그림자로 넣었어요.
살짝 뜨는 정도라 표가 흔들려 보이지 않습니다.

`prefers-reduced-motion: reduce`가 켜져 있으면 `index.css`의 전역 블록이
모든 애니메이션과 트랜지션을 한 번에 끕니다. 컴포넌트마다 따로 챙기지 않아도 돼요.
